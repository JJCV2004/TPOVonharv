03. COMPARATIVA PYTHON & DEFENSA ORAL

Rol Asesor IT · Especificación para Agencia Web
❌ MALA PRÁCTICA (VULNERABLE) formulario_vulnerable.py 
# [FALLA 1]: Sin validación ni listas blancas
import sqlite3

def guardar_presupuesto_vulnerable(tipo, fecha, nombre, notas):
    conn = sqlite3.connect("vonharv.db")
    cursor = conn.cursor()

    # [FALLA 2]: Concatenación directa con f-string
    # Mezcla datos del usuario con órdenes SQL
    sql = f"""
        INSERT INTO solicitudes (tipo, fecha, nombre, notas)
        VALUES ('{tipo}', '{fecha}', '{nombre}', '{notas}');
    """

    # [FALLA 3]: executescript permite inyectar ';' y DROP TABLE
    cursor.executescript(sql)
    conn.commit()
¿Por qué falla? No existe separación entre el comando del programador y el texto del usuario. El motor SQL ejecuta cualquier instrucción inyectada tras una comilla simple (').
✅ BUENA PRÁCTICA (3 CAPAS BACKEND) formulario_seguro.py 
# [CAPA 1]: Lista Blanca con Expresiones Regulares (Regex)
import sqlite3, html, re
REGEX_NOMBRE = re.compile(r"^[a-zA-ZáéíóúÁÉÍÓÚñÑ\s'.-]{2,80}$")

def guardar_presupuesto_seguro(tipo, fecha, nombre, notas):
    if not REGEX_NOMBRE.match(nombre):
        raise ValueError("Nombre inválido bloqueado por Lista Blanca")

    # [CAPA 2]: Sanitización HTML contra Stored XSS
    notas_limpias = html.escape(notas.strip())

    with sqlite3.connect("vonharv.db") as conn:
        # [CAPA 3]: Consulta Parametrizada (Prepared Statement)
        sql = "INSERT INTO solicitudes VALUES (?, ?, ?, ?);"
        conn.execute(sql, (tipo, fecha, nombre, notas_limpias))
¿Por qué es invulnerable? El motor SQL precompila la estructura con marcadores ? y recibe los datos por un canal separado como simples literales de texto inofensivos.

1. ¿POR QUÉ EN EL BACKEND?

Toda validación en el navegador (JavaScript/HTML) se salta fácilmente con Burp Suite, Postman o curl. Por eso la validación y parametrización obligatoria se exige en el servidor.
